# Pokemon Z Team Training for Archipelago

An [Archipelago](https://archipelago.gg) world for **Pokemon Z Team Training**, the Dragon Ball Z hack of Pokémon
FireRed by Z-MAX, built on the [Pokémon FireRed and LeafGreen](https://github.com/vyneras/Archipelago) world (1.1.5).

- Players only need a clean **Pokémon FireRed (USA) 1.0** ROM (md5 `e26ee0d44e809351c8ce2d73c7400cdd`).
  The hack's patch is bundled and applied when a `.apztt` patch file is opened.
- Every FireRed/LeafGreen option, location and piece of logic works. The game shows the hack's characters, moves,
  items, trainers, text, graphics and music. Map layouts, events and scripts stay Archipelago's, which the logic needs.
- Plays with Archipelago's BizHawk Client and `connector_bizhawk_generic.lua`.
- Comes with a PopTracker / Universal Tracker pack.

## Repository layout

```
worlds/pokemon_z_team_training/   the apworld source (zip this folder to get the .apworld)
tracker/                          the PopTracker pack (generated by tools/port_tracker.py)
examples/                         example player YAMLs: default, full sanity, full randomizer
tools/                            build tools: transplant, data regeneration, packaging, tests
  data/                           symbol maps (vanilla FireRed, Archipelago base ROM)
  upstream/pokemon_frlg/          the upstream FireRed/LeafGreen world 1.1.5 the build starts from
  testing/                        BizHawk Lua smoke test
```

`build/` and `dist/` are local outputs and are not tracked. No ROM is stored in this repository.

## How it works

At patch time the world runs four steps (`worlds/pokemon_z_team_training/rom.py`, `zt_patch.py`):

1. `build_hack_rom`: apply the bundled Pokemon Z Team Training BPS to the player's FireRed ROM, in memory.
2. `apply_bsdiff4`: build the Archipelago FireRed base ROM from the same clean ROM (the upstream patch, unchanged).
3. `apply_transplant`: run `data/ztt_plan.bin`, a list of copies (hack ROM offset → Archipelago ROM offset) and
   pointer writes. The plan holds offsets and pointers only; every content byte is read from the hack ROM.
4. `apply_tokens`: the usual per-seed Archipelago data.

The plan and the regenerated generation data (`data/extracted_data.json`, evolution events) come from
`tools/make_apworld.py`. See [tools/README.md](tools/README.md) for how to rebuild.

## Known limitations

These come from how the hack is built, not from missing work:

- **Maps and story.** The hack rebuilt many maps (collision, warps, buildings) and wrote its own story scripts.
  Archipelago's locations and logic are tied to FireRed's maps, so those stay. Edited areas are taken from the hack
  wherever collision and tile behaviour match; towns the hack rebuilt keep FireRed's tileset art, since the hack's art
  only fits its own layouts.
- **Pokédex numbering** stays FireRed's: the hack's numbering gives five species the same numbers as Gen 3 Pokémon,
  which would break Pokédex checks. Each character still gets its own entry.
- **Cries** stay FireRed's: the hack points the new characters at a picture, not at sound data.
- **Story-only features** (special-moveset gifts, story battle backgrounds) are started only by the hack's scripts.
- **Shiny PICCOLO** uses its normal palette: the hack's shiny palette for it is empty.
